# CI/CD Exceptions and Waivers

## Purpose

This document records approved exceptions and waivers against applicable CI/CD Standardization Framework controls for the Databricks Unified Data Access Automation (UDAA) repository.

An exception is required when a CI/CD control applies to this repository but cannot currently be fully implemented.

A control must not be classified as **Not Applicable** simply because implementation is incomplete.

---

## Exception Process

When an applicable CI/CD control cannot be implemented, the repository team must document:

| Requirement | Details |
|---|---|
| Control | CI/CD control requiring the exception |
| Reason | Business or technical reason the control cannot currently be implemented |
| Risk | Risk introduced by the control deviation |
| Compensating Control | Temporary or alternative control used to reduce the risk |
| Remediation | Planned action to achieve compliance |
| Owner | Person or team responsible for remediation |
| Approval | Required governance / risk approval |
| Expiry Date | Date by which the exception must be reviewed or remediated |
| Tracking Reference | Jira / ServiceNow / Governance record |

## Exception Review

Active exceptions must be reviewed as part of the repository governance review.

The review must confirm that:

- The exception is still required.
- The associated risk remains understood and accepted.
- Compensating controls remain effective.
- Remediation activities are progressing.
- The approval has not expired.
- The exception is closed when the required control has been implemented.

The enterprise-approved exception, risk, Jira, ServiceNow, or governance system remains the authoritative approval record.

This document provides the repository-level reference and traceability to those records.
